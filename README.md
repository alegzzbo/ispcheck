# ispcheck

Утилита диагностики интернет-соединения для абонентов провайдера. Запускается одним файлом, за минуту собирает данные о сети и отправляет отчёт в техподдержку. Сделана на Rust, окно на [egui](https://github.com/emilk/egui). Работает на Windows, Linux и macOS.

## Что проверяет

| Проверка | Что показывает |
|---|---|
| Тип подключения и линк | Wi-Fi или кабель, согласованная скорость приёма и передачи. Для Wi-Fi: SSID, сигнал, стандарт (Wi-Fi 4/5/6/7), диапазон (2,4 / 5 / 6 ГГц) и канал |
| Шлюз | Адрес шлюза по умолчанию, задержка, джиттер, потери |
| Внешний IP | IPv4, а также IP через системный прокси (и отличается ли он от прямого) |
| DNS | DNS-серверы адаптера, upstream-резолвер (виден из интернета), системный DNS против публичных (1.1.1.1, 8.8.8.8, 77.88.8.8), DoH по RFC 8484 |
| Пинг | 1.1.1.1, 8.8.8.8 и узлы провайдера: задержка, джиттер, потери (ICMP, при недоступности TCP/443) |
| Сайты | Список для проверки и сайты, которые указал пользователь (с диагностикой DNS) |
| Скорость | OpenSpeedTest провайдера: HTTP/1.1, 8 потоков, первые 2 с не учитываются |
| Трассировка и MTR | Таблица по хопам, смены маршрута, статистика по путям: на каком пути цель перестаёт отвечать |

Если интернета нет (не задан шлюз, нет выхода на публичные адреса), тест останавливается сразу, а не перебирает таймауты. Замер скорости пропускается, если сервер OpenSpeedTest недоступен.

В конце формируется краткое резюме для разговора с поддержкой по телефону. Предупреждения выводятся, если порт работает на 100 Мбит/с и ниже, сигнал Wi-Fi слабый, дуплекс не full или замер упёрся в скорость линка.

Отчёт можно скопировать или отправить в поддержку кнопкой. Логин хранится локально.

## Скачать

Готовые сборки лежат в [Releases](../../releases):

- `ispcheck-windows-amd64.exe` (статическая CRT, дополнительные библиотеки не нужны)
- `ispcheck-linux-amd64`
- `ispcheck-macos-universal` (Intel и Apple Silicon)

К каждому файлу прилагается `.sha256`.

## Консольная версия (без GUI)

Для серверов, SSH и систем без графики есть сборка без окна и OpenGL. Это отдельный бинарь `ispcheck-cli-linux-amd64` (статический, не зависит от версии glibc) в Releases. Собрать самостоятельно: `cargo build --release --no-default-features` (под Windows и macOS тоже работает). Автообновления в консольной версии нет.

```
ispcheck                                  # полная проверка, журнал в консоль
ispcheck -s example.com -s other.org      # + свои сайты
ispcheck -m 8.8.8.8 -c 30                 # + MTR (0 циклов = до Ctrl+C)
ispcheck --no-check -m 8.8.8.8            # только MTR
ispcheck --json > report.json             # итог в JSON (журнал уходит в stderr)
ispcheck --send --login ivanov --note "тормозит вечером"
```

Цвета включаются только при выводе в терминал (отключить: `--no-color` или `NO_COLOR`). Код возврата: 0, если ошибок (✖) нет, 1, если они были, 2 при неверных параметрах.

## Платформы и права

- **Windows:** права администратора не нужны. ICMP идёт через `iphlpapi`, данные об адаптерах и Wi-Fi через WinAPI, прокси из реестра. Внешние процессы (`netsh` и др.) не запускаются.
- **Linux:** для MTR и трассировки нужен raw ICMP: `sudo setcap cap_net_raw+ep ./ispcheck` либо запуск от root. Без этого работает только обычный пинг. Данные Wi-Fi берутся из `iw`, если он установлен.
- **macOS:** в Releases лежит `ispcheck-macos-universal.dmg`: откройте его и перетащите «ISP Check» в «Программы». Приложение подписано «ad hoc» (без платного Apple Developer ID), поэтому при первом запуске macOS спросит подтверждение: ПКМ по приложению → «Открыть» → «Открыть» (на macOS 15 и новее ещё «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть»). Либо снять карантин: `xattr -dr com.apple.quarantine "/Applications/ISP Check.app"`. Чтобы предупреждения не было совсем, нужны подпись Developer ID и нотаризация (платная программа Apple). Wi-Fi определяется через CoreWLAN (скорость, сигнал в дБм, диапазон, канал, стандарт). SSID macOS 14+ показывает только приложениям с доступом к геолокации, поэтому для обычного бинарника он будет пустым. Системный прокси и адрес PAC читаются из `scutil --proxy`.
- Нужен OpenGL 2.0 и выше. На виртуальных машинах без графического ускорения окно может не открыться.

## Сборка

```
cargo build --release
```

Подробные шаги для каждой ОС (rustup, Visual Studio Build Tools или MSYS2, зависимости Linux, универсальный бинарь macOS, кросс-сборка) описаны в [BUILD.md](BUILD.md).

Сборку под все платформы делает GitHub Actions ([.github/workflows/build.yml](.github/workflows/build.yml)): при пуске тега `vX.Y.Z` версия подставляется в `Cargo.toml`, а файлы прикрепляются к релизу.

```
git tag v1.0.1
git push origin v1.0.1
```

## Настройка под своего провайдера

Все параметры лежат в [`src/config.rs`](src/config.rs):

- `ISP_NAME`, `ISP_HOSTS`: название и узлы провайдера для пинга и трассировки
- `OST_URL`: адрес OpenSpeedTest (без слэша в конце), `SPEED_SECONDS`, `THREADS`
- `SITES`, `DNS_DOMAINS`, `PUBLIC_DNS`, `DOH_SERVERS`: что проверять
- `REPORT_URL`, `REPORT_TOKEN`: куда отправлять отчёты (если `REPORT_URL` пустой, кнопка отправки не показывается)
- `UPDATE_URL`, `UPDATE_PUBKEY`: автообновление
- `MTR_CYCLES`, `MTR_DEFAULT_HOST`

Версия берётся из `Cargo.toml`. Иконка: положите `favicon.ico` рядом с `Cargo.toml` (она попадёт в окно и, при сборке на Windows, в exe), файл нужно закоммитить.

## Приём отчётов

Скрипт [`server/receive.php`](server/receive.php) принимает JSON методом POST, проверяет токен `X-Report-Token`, ограничивает частоту запросов и отправляет письмо в поддержку (и сохраняет архив). Перед использованием замените `CHANGE_ME` на свой токен, одинаковый в `REPORT_TOKEN` и в PHP, и пропишите адреса `MAIL_TO` / `MAIL_FROM`.

Токен вшит в бинарник, поэтому защищает только от случайных запросов, а не от целенаправленных.

В отчёт попадают: логин, версия, время, имя компьютера, ОС, внешний IP (и через прокси), данные о линке (включая SSID для Wi-Fi), комментарий и текст отчёта. Сообщите об этом пользователям.

## Автообновление

При запуске программа запрашивает `UPDATE_URL` и, если версия новее, предлагает обновиться. Формат `latest.json`:

```json
{
  "version": "1.0.1",
  "notes": "Что изменилось",
  "files": {
    "windows-amd64": { "url": "https://…/ispcheck.exe", "sha256": "…", "sig": "base64" },
    "linux-amd64":   { "url": "…", "sha256": "…", "sig": "…" },
    "darwin-arm64":  { "url": "…", "sha256": "…", "sig": "…" }
  }
}
```

Файл скачивается, проверяется контрольная сумма и подпись ed25519 (подписывается сам digest SHA-256, 32 байта, ключ `UPDATE_PUBKEY`), затем exe подменяется, старый сохраняется как `.old`. Утилиты для генерации ключей и подписи в репозитории пока нет.

## Структура

```
src/main.rs      окно, тема, лог
src/checks.rs    все проверки, резюме, отправка отчёта
src/mtr.rs       MTR, пути и смены маршрута
src/dns.rs       DNS wire-формат, UDP-запросы, системный резолвер
src/update.rs    автообновление
src/sys/         платформенный код (windows.rs, unix.rs): ICMP, шлюз, адаптеры, Wi-Fi, прокси
src/config.rs    настройки провайдера
assets/          шрифт символов (подмножество DejaVu Sans Mono)
server/          receive.php
```
